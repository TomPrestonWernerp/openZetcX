# 三书一体 AI 智能审核工作流

## 概述

本技能用于对「三书一体」三份文档进行全要素智能审核。可独立审核任一文档，也可三书联动交叉校验。

**三书范围：**
| 文档 | 归属skill | 审核规则数 | 否决项数 |
|:----|:---------|:---------:|:-------:|
| 突发环境事件应急预案 | enterprise-emergency-plan-generator | 43条（C族） | 4条（F-03/F-05/F-09/F-10） |
| 环境风险评估报告 | risk-assessment-report-compiler | 23条（A族） | 5条（F-01/F-02/F-04/F-06/F-07） |
| 应急资源调查报告 | resource-investigation-compiler | 14条（B族） | 1条（F-08） |
| 行业特异性（跨文档） | — | 13条（E族） | 1条（E-04作为否决项） |
| 数据一致性（跨文档） | — | 9条（D族） | — |
| **合计** | | **103条** | **12条** |

**参考规则库：** `改革方案/应急预案AI智能审核规则表.xlsx`

---

## ⚠️ 核心原则

### 原则一：规则引擎硬算，LLM 不参与数值计算
以下审核必须由规则引擎执行，LLM 不得接触数字计算：
- Q 值计算和复核（A-01~A-08, F-01, F-02）
- M 值评分核验（A-09~A-12）
- E 值判定校验（A-13, A-14）
- 等级矩阵查表（A-15, F-02）
- 应急池核算公式校验（B-04~B-10, F-08）
- 标准引用时效性查表（C-03, E-09）
- 数据一致性交叉比对（D-01~D-09）

### 原则二：否决项优先
所有否决项（CRITICAL）必须在审核流程**第一步最优先**处理。触发任何一项否决项，直接输出「不通过」，不再进行后续评分。

### 原则三：输出结构化 JSON
审核结果必须以标准 JSON 格式输出，包含分文档评分+跨文档一致性+行业特异性检查。

## 审核模式选择

本skill支持3种审核模式，根据输入自动判断：

| 模式 | 输入 | 输出 |
|:---|:----|:----|
| **单文档模式** | 1个DOCX | 该文档的独立审核报告 |
| **双文档模式** | 2个DOCX | 两文档分别评分+交叉校验 |
| **三书一体模式** | 3个DOCX | 三文档总分+交叉校验+行业检查 |

如只输入1个DOCX，默认走单文档模式。如需三书一体审核，必须同时传入`应急预案.docx`+`风险评估报告.docx`+`资源调查报告.docx`。

## 阶段一：解析预处理

### 步骤1：读取审核规则库
- 从 Excel 规则表中加载所有规则（103条）
- 按**所属文档**分组：
  ```python
  rules_by_doc = {
      'risk_assessment':  ['F-01','F-02','F-04','F-06','F-07'] + ['A-01'~'A-18'],
      'resource_investigation': ['F-08'] + ['B-01'~'B-13'],
      'plan': ['F-03','F-05','F-09','F-10'] + ['C-01'~'C-40'],
      'industry': ['E-01'~'E-13'],
      'data_consistency': ['D-01'~'D-09'],
  }
  ```
- 加载行业特异性规则（C33 金属表面处理）
- 加载标准时效性台账（19条核心标准）

### 步骤2：解析三份文档
- 读取 DOCX 文件（支持1~3个）
- 提取文本内容，按章节结构分割
- 提取表格数据
- 提取关键数字字段：Q值、M值、E值、风险等级、应急池容量、员工人数、化学品清单等
- 提取标准引用列表

### 步骤3：加载企业原始数据（从GLOBAL表或自检JSON）
- 读取企业自检报告JSON（如有则优先使用）
- 关键字段：物质清单、临界量、工艺参数、池容参数

## 阶段二：否决项检查（逐文档进行）

按**所属文档**分组执行否决项检查：

### 风险评估报告否决项（5条）
| 编号 | 检查项 | 检查方法 |
|:----|:------|:--------|
| F-01 | 风险物质严重遗漏 | Q值总量 vs 自评Q水平→自评Q1但实际Q≥10 |
| F-02 | Q/M/E取值错误 | 规则引擎重新计算三值→与文档声明不符 |
| F-04 | 剧毒物质遗漏 | 行业物质库比对→含氰/铬/HF未列 |
| F-06 | 环境风险受体严重遗漏 | 文本提取→500m/5km人口缺失 |
| F-07 | 临界量取值错误 | 临界量台账比对→与HJ 941-2018不符 |

### 应急预案否决项（4条）
| F-03 | 引用已废止标准 | 标准台账查表→包含废止标准 |
| F-05 | 组织机构完全缺位 | LLM+格式检查→无职责描述章节 |
| F-09 | 等级与风险评估矛盾 | 跨文档比对→三书等级不一致 |
| F-10 | 有毒气体泄漏无监测 | 行业规则→涉气企业无监控 |

### 应急资源调查否决项（1条）
| F-08 | 应急池容量未核算 | 规则引擎→无V总公式和计算 |

### 行业否决项（1条）
| E-04 | 含氰企业无解毒剂 | 行业物资库→含氰但物资无解毒剂 |

### 含氰企业附加否决（1条）
| C-20 | 含氰企业无HCN处理专案 | 行业规则→含氰无专项方案 |

**如果任何一条 FAIL，在总分标记为「不通过」**，但继续执行其他不相关文档的评分（例如只有风险评估报告触发否决，应急预案和资源调查报告仍可评分）。

## 阶段三：分文档要素评分

### 3.1 风险评估报告评分（A族18条）
规则引擎硬算（全量15条）+ LLM检查（3条）：
- A-01~A-08：Q值计算（物质清单/折纯/槽液分拆/酸洗槽计入/别名/累加/水平划分/涉气涉水分列）
- A-09~A-15：M值（评分+工艺+淘汰+水平）+ E值（人口+敏感目标）+ 等级矩阵
- A-16：重大危险源辨识
- A-17~A-18：风险单元完整性 + 最大可信事故（LLM）
- E-01~E-13：13条行业特异性规则（判断触发条件后分别执行）

### 3.2 应急资源调查报告评分（B族13条）
规则引擎硬算（全量10条）+ LLM检查（3条）：
- B-01~B-02：物资清单完整性 + 数量合理性
- B-04~B-10：应急池核算（V1~V5逐项校验+对比结论+F-08否决）
- B-11~B-13：队伍人员 + 外部联动协议 + 个人防护
- 行业触发检查：E-04（解毒剂）/ E-05（葡萄糖酸钙）/ E-12（酸碱中和）

### 3.3 应急预案评分（C族40条+建议项3条）
规则引擎硬算（20条）+ LLM检查（23条）：
- C-01~C-12：总则+基本情况（编制目的/依据/适用范围/事件分级/工作原则/预案体系）
- C-13~C-24：应急响应（响应分级/接警/处置场景×5/步骤/疏散/监测/终止）
- C-26~C-33：预防预警/信息公开/后期处置/应急保障/预案管理/附则
- C-34~C-40：附件（联络表/报告表/图纸×3/现场处置方案）

### 评分方法
```
总分 = 100（每份文档独立计分）
否决项触发 → 该文档不通过（其他文档正常评分）

严重项(MAJOR): 扣10~15分/条
一般项(MINOR): 扣3~5分/条
建议项(SUGGESTION): 扣1分/条

评分等级：
- ≥90分：直接通过
- ≥75分：有条件通过（需整改严重项）
- <75分：不通过
```

## 阶段四：跨文档数据一致性检查（D-01~D-09）

在完成三个文档的独立解析后，执行跨文档一致性交叉校验：

| 编号 | 检查项 | 提取位置（三书） | 判定条件 |
|:----|:------|:--------------|:--------|
| D-01 | 企业名称一致性 | 预案2.1 / 风险评估3.1 / 资源调查2.1 | 完全一致 |
| D-02 | 风险物质清单一致性 | 预案3.2 / 风险评估3.5 / 资源调查2.2 | 物质名称和分类一致 |
| D-03 | Q值一致性 | 预案3.2.1+3.3.1 / 风险评估7.3.1+7.4.1 | 涉气/涉水Q值分别一致 |
| D-04 | 风险等级一致性 | 预案3.4 / 风险评估7.5 / 资源调查2.2 | 等级表征完全一致 |
| D-05 | 应急池容量一致性 | 预案4.2 / 风险评估5.2.3 / 资源调查3.4.2 | 计算值和现有值一致 |
| D-06 | 化学品储量和一致性 | 预案3.2 / 风险评估3.5 | 最大值（非年用量）一致 |
| D-07 | 员工人数一致性 | 预案2.1 / 风险评估3.1 / 资源调查2.1 | 人数一致 |
| D-08 | 设备列表一致性 | 预案2.5 / 风险评估3.2.5 | 关键设备一致 |
| D-09 | 固废数据一致性 | 预案2.6 / 风险评估3.2.6 | 危废种类/处置方式一致 |

**无需三书齐备的情况：** 如果只收到2份文档，只校验这2份的交集字段。如果只收到1份，不执行D族检查但标记「数据一致性：未交叉校验」。

## 已知限制与处理策略

| 限制 | 处理策略 |
|:----|:--------|
| 只收到1份文档 | 自动降级为单文档模式，D族跳过 |
| GIS 数据缺失 | 标记「需获取GIS数据」，不记入扣分 |
| 企业未上传图纸 | 标记「企业需补充」，不扣分 |
| 匿名物资无法匹配别名 | 返回「未匹配别名，请人工确认」，扣3分 |
| 三份文档中某份版本不一致 | 以最新生成日期为准，标记警告 |
